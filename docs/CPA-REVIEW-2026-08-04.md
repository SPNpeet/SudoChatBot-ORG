## 2. สิ่งที่ตรวจแล้วถูกต้อง (ไม่ต้องแตะ)

**คำนวณซ้ำด้วย decimal (ROUND_HALF_UP) ตรงทุกใบ:**
- 5,000 แยกนอก → VAT 350.00 · รวม 5,350.00 · หัก 3% = 150.00 · จ่ายจริง 5,200.00 ✓
- 2,380 รวมใน → VAT 155.70 (2380×7/107) · ก่อนภาษี 2,224.30 ✓ (ใบลดหนี้ CN-2026-0001)
- 4,000 แยกนอก → 280.00 / 4,280.00 / หัก 120.00 / 4,160.00 ✓
- 2,920 แยกนอก → 204.40 / 3,124.40 ✓
- ภาษีขาย ส.ค. (invoice 5 ใบ − ใบลดหนี้ 1 ใบ) = **1,184.40 = สมุดรายวัน 1,184.40** ต่าง 0.00 ✓

**กวาด SQL ทั้งระบบ (ทุกกิจการ) — ศูนย์ทุกด่าน:**
สมุดรายวันไม่สมดุล 0 · WHT ฐานไม่ใช่ก่อน VAT 0 (ถูกตาม ม.50) · ก่อนภาษี+VAT≠รวม 0 ·
เลขเอกสารซ้ำ 0 · รับชำระเกิน 0 · สต๊อกติดลบ 0

**เชิงโครงสร้างที่ทำถูกตามกฎหมาย:**
- Tax point แยกสินค้า (ม.78) / บริการ (ม.78/1) พร้อมตาราง `vat_recognitions` รับรู้ตอนรับเงิน ✓
- ใบลดหนี้เข้า ภ.พ.30 เดือนที่ออก พร้อมเหตุผลบนเอกสารตาม ม.86/10 และอ้างใบกำกับเดิม ✓
- เตือน ม.86/4 บนหน้าพิมพ์เมื่อข้อมูลผู้ซื้อไม่ครบ (เห็นจริงบน production) + สาขาแยกช่องตามประกาศ 199 ✓
- อัตรา VAT อยู่ในตาราง `vat_rates` มีวันเริ่ม-สิ้นสุด พ้นช่วง = ระบบเตือน ไม่เดาต่อ ✓
- เครื่องตรวจปัดเศษ 400,000 เคสรันทุกครั้งก่อน push (`npm run check`) ✓
- ยกเลิกเอกสาร = กลับรายการ ไม่ลบ + audit log ✓ · period lock มีแล้ว ✓ · Manual JV มีแล้ว ✓

## 3. ประเด็นที่พบ

### 🔴 1. ไฟล์ RD Prep ยังไม่เคยทดสอบนำเข้าโปรแกรมจริง
- **อาการ:** ไฟล์ .txt (TIS-620/พ.ศ./คั่น `|`) สร้างได้ แต่ยังไม่มีใครโหลดเข้า RD Prep จริงสักครั้ง
- **ฐาน:** ตำแหน่งฟิลด์ RD Prep เปลี่ยนตามเวอร์ชัน — ห้ามรับรองไฟล์ที่ยังไม่ทดสอบ
- **ผลกระทบ:** ถ้าไฟล์เพี้ยน เจ้าของรู้ตัววันยื่นพอดี → ยื่นช้า = เงินเพิ่ม 1.5%/เดือน (ม.27)
- **วิธีแก้:** เจ้าของทดสอบด้วยกิจการ **`dd`** (กิจการ King ไม่มีเอกสาร VAT/WHT → ได้ไฟล์เปล่า สรุปผิด)
  **ห้ามติ๊ก "บรรทัดแรกชื่อคอลัมน์"** · เดดไลน์กระดาษ **7 ส.ค. 2569** / e-filing ~15 ส.ค.

### 🔴 2. เอกสารวันที่ผิด 5 ใบ รอแก้ผ่านหน้าเว็บเท่านั้น
- **อาการ:** `RC-2026-0001/0002/0003` (กิจการ `577c7e11` ชุดเก่า) วันที่ไม่ตรงวันจริง (วันจริงอยู่ในหมายเหตุแต่ละใบ) ·
  `EXP-2026-0003` ของอีกบัญชีลงปี **2069** (ตรวจวันนี้ยังค้าง 1 ใบ) · ใบ 54 บาทซ้ำในกิจการ King
- **ฐาน:** วันที่เอกสารกำหนดเดือนภาษี — ผิดเดือน = ภ.พ.30 ผิดงวด
- **วิธีแก้:** ยกเลิก → ออกใหม่ผ่านหน้าเว็บ (ห้าม SQL — สมุดรายวันกับเอกสารจะแยกจากกัน)

### 🟠 3. ข้อมูลตัวอย่าง 25 ใบใน 6 กิจการยังลงสมุดรายวันอยู่
- **อาการ:** ผู้ใช้กด "ลองด้วยข้อมูลตัวอย่าง" แล้วไม่กดล้าง — ตัวเลขปนของจริง
- **การควบคุมที่มีแล้ว:** แบนเนอร์เตือน + ปุ่มล้าง (ออกแบบถูก) แต่พฤติกรรมจริงคือคนไม่ล้าง
- **วิธีแก้ที่เสนอ (ยังไม่ได้ทำ — รอไฟเขียว เพราะเป็นกฎใหม่):** บล็อกการดาวน์โหลด
  ชุดส่งนักบัญชี/ไฟล์ RD เมื่อกิจการยังมีเอกสารตัวอย่างค้าง พร้อมปุ่ม "ล้างแล้วโหลดต่อ"
  — เข้มเกินปลอดภัยกว่าปล่อยตัวเลขปลอมไปถึงมือนักบัญชี

### 🟠 4. งวดของเอกสารที่ยกเลิกข้ามเดือน — การตัดสินใจเชิงนโยบาย
- **อาการ:** กิจการ `8ae32765` ยกเลิกเอกสารของ มิ.ย./ก.ค. ในเดือน ส.ค. → สมุดรายวันกลับรายการ
  ในเดือนที่ยกเลิก (ถูก — ไม่เปิดงวดปิดแล้ว) แต่รายงานตัดเอกสารออกจากเดือนที่ออก
  → รายงานงวดที่ยื่นแล้วเปลี่ยนย้อนหลัง (ผลรวมสุทธิ = 0 ยอดไม่ผิด ผิดที่งวด)
- **ทางเลือก:** (ก) สอนผู้ใช้: เอกสารที่ยื่น ภ.พ.30 แล้วให้ใช้ใบลดหนี้ ไม่ใช่ปุ่มยกเลิก
  (ระบบมี period lock + ใบลดหนี้ครบแล้ว) หรือ (ข) คงพฤติกรรมปัจจุบัน
- **ต้องให้ผู้ทำบัญชี/CPA เลือก** — ผู้รีวิวไม่ตัดสินแทน

### 🟡 5. เลขฉบับ พ.ร.ฎ. ต่ออายุ VAT
- เพิ่มแถว `vat_rates` (1 ต.ค. 2569 – 30 ก.ย. 2570) แล้ว แต่โน้ตยังไม่มีเลขฉบับ พ.ร.ฎ.
  — ให้เจ้าของเปิดราชกิจจาฯ ยืนยันเลขฉบับแล้วเติม (กันสับสนกับฉบับ 799 เดิม)
