สิ่งที่เหลือคืองานปฏิบัติการฝั่งเจ้าของ + การเปิดสวิตช์รับเงิน ไม่ใช่บั๊กบัญชี

## 2. สิ่งที่ตรวจแล้วถูกต้อง (ไม่ต้องแตะ)

**คำนวณซ้ำด้วย decimal (ROUND_HALF_UP) ตรงทุกใบ:**

| เอกสาร | ตรวจ | ระบบแสดง | ผล |
|---|---|---|---|
| 5,000 แยกนอก + หัก 3% | VAT 350.00 · รวม 5,350.00 · หัก 150.00 · จ่ายจริง 5,200.00 | เหมือนกัน | ✓ |
| 2,380 รวมใน (ใบลดหนี้) | VAT 155.70 (2380×7/107) · ก่อนภาษี 2,224.30 | เหมือนกัน | ✓ |
| 4,000 แยกนอก + หัก 3% | 280.00 / 4,280.00 / 120.00 / 4,160.00 | เหมือนกัน | ✓ |
| 2,920 แยกนอก | 204.40 / 3,124.40 | เหมือนกัน | ✓ |
| **ภาษีขาย ส.ค. (5 ใบ − ใบลดหนี้ 1)** | **1,184.40** | สมุดรายวัน 1,184.40 | **ต่าง 0.00** ✓ |

**กวาด SQL ทุกกิจการ — ศูนย์ทุกด่าน:** สมุดรายวันไม่สมดุล 0 · WHT ฐานไม่ใช่ก่อน VAT 0 (ถูกตาม ม.50) ·
ก่อนภาษี+VAT≠รวม 0 · เลขเอกสารซ้ำ 0 · รับชำระเกิน 0 · สต๊อกติดลบ 0 · client_error 7 วัน 0

**เชิงโครงสร้างที่ถูกตามกฎหมาย:** tax point แยกสินค้า (ม.78)/บริการ (ม.78/1) + ตาราง `vat_recognitions` ·
ใบลดหนี้เข้างวดที่ออกพร้อมเหตุผลตาม ม.86/10 และอ้างใบกำกับเดิม · เตือน ม.86/4 บนหน้าพิมพ์เมื่อข้อมูลผู้ซื้อไม่ครบ ·
สาขาแยกช่องตามประกาศอธิบดีฯ 199 · อัตรา VAT อยู่ในตารางมีวันเริ่ม-สิ้นสุด ·
เครื่องตรวจปัดเศษ 400,000 เคสรันก่อน push ทุกครั้ง · ยกเลิก = กลับรายการ + audit log · period lock · Manual JV

## 4. ประเด็นที่พบ

### 🔴 1. ไฟล์ RD Prep ยังไม่เคยทดสอบนำเข้าโปรแกรมจริง
**ฐาน:** ตำแหน่งฟิลด์ RD Prep เปลี่ยนตามเวอร์ชัน — ห้ามรับรองไฟล์ที่ยังไม่ทดสอบ
**ผลกระทบ:** ไฟล์เพี้ยน → รู้ตัววันยื่นพอดี → ยื่นช้า = เงินเพิ่ม 1.5%/เดือน (ม.27)
**วิธีแก้:** ทดสอบด้วยกิจการ **`dd`** (กิจการ King ไม่มีเอกสาร VAT/WHT → ได้ไฟล์เปล่า สรุปผิด) ·
**ห้ามติ๊ก "บรรทัดแรกชื่อคอลัมน์"** · เดดไลน์กระดาษ **7 ส.ค. 2569**

### 🔴 2. เอกสารวันที่ผิดรอแก้ผ่านหน้าเว็บ
`RC-2026-0001/0002/0003` วันที่ไม่ตรงวันจริง (วันจริงอยู่ในหมายเหตุ) · `EXP-2026-0003` ลงปี **2069** · ใบ 54 บาทซ้ำ
**ฐาน:** วันที่เอกสารกำหนดเดือนภาษี — ผิดเดือน = ภ.พ.30 ผิดงวด
**วิธีแก้:** ยกเลิก → ออกใหม่ผ่านหน้าเว็บ (**ห้าม SQL** — สมุดรายวันกับเอกสารจะแยกจากกัน)

### 🔴 3. รับเงินสำเร็จ 0 บาท ทั้งที่มีคนพยายามจ่าย 7 ครั้ง
`platform_billing_settings.slip_provider = 'manual'` ไม่มีคีย์ตรวจสลิป → ทุกรายการรออนุมัติมือ
**ระบบตรวจสลิปอัตโนมัติ + เปิดแพ็กทันที เขียนเสร็จแล้วและใช้ได้ — แค่ไม่เคยเปิด**
**วิธีแก้ (15 นาที ไม่ต้องแก้โค้ด):** สมัคร EasySlip หรือ SlipOK → ใส่คีย์ที่ `/dashboard/admin/billing`
→ เปลี่ยน `slip_provider` จาก manual · และกด "เชื่อมต่อ LINE" ที่ `/dashboard/settings?s=notify`
(ตรวจแล้ว: LINE 0 · Push 0 → การแจ้งเตือน "มีคนรอจ่ายเงิน" ยังส่งไปไม่ถึงใคร)

### 🟠 4. ข้อมูลตัวอย่าง 25 ใบใน 6 กิจการยังลงสมุดรายวัน
มีแบนเนอร์เตือน + ปุ่มล้างแล้ว (ออกแบบถูก) แต่พฤติกรรมจริงคือคนไม่ล้าง
**ข้อเสนอ (ยังไม่ทำ — เป็นกฎใหม่ รอไฟเขียว):** บล็อกดาวน์โหลดชุดส่งนักบัญชี/ไฟล์ RD
เมื่อยังมีเอกสารตัวอย่างค้าง พร้อมปุ่ม "ล้างแล้วโหลดต่อ" — เข้มเกินปลอดภัยกว่าปล่อยตัวเลขปลอมถึงมือนักบัญชี

### 🟠 5. งวดของเอกสารที่ยกเลิกข้ามเดือน
กิจการ `8ae32765` ยกเลิกเอกสาร มิ.ย./ก.ค. ในเดือน ส.ค. → สมุดรายวันกลับรายการเดือนที่ยกเลิก (ถูก — ไม่เปิดงวดปิดแล้ว)
แต่รายงานตัดเอกสารออกจากเดือนที่ออก → รายงานงวดที่ยื่นแล้วเปลี่ยนย้อนหลัง (**ผลรวมสุทธิ = 0 ยอดไม่ผิด ผิดที่งวด**)
**ทางเลือก:** (ก) สอนผู้ใช้ว่าเอกสารที่ยื่น ภ.พ.30 แล้วให้ใช้ **ใบลดหนี้** ไม่ใช่ปุ่มยกเลิก (ระบบมี period lock + ใบลดหนี้ครบแล้ว)
หรือ (ข) คงพฤติกรรมปัจจุบัน — **ต้องให้ผู้ทำบัญชี/CPA เลือก ผู้รีวิวไม่ตัดสินแทน**

### 🟡 6. เลขฉบับ พ.ร.ฎ. ต่ออายุ VAT
เพิ่มแถว `vat_rates` แล้ว แต่โน้ตยังไม่มีเลขฉบับ — เปิดราชกิจจาฯ ยืนยันแล้วเติม (กันสับสนกับฉบับ 799 เดิม)
