## 3. สูตรคำนวณ — จุดที่ขอให้ตรวจก่อนเป็นอันดับแรก

ทั้งหมดอยู่ใน `src/lib/finance.ts` → `calcDocTotals()` ฟังก์ชันเดียว ไม่มีที่อื่นคำนวณซ้ำ

```
ฐาน (base)     = ผลรวม(จำนวน × ราคาต่อหน่วย) − ส่วนลด

โหมดแยกนอก (exclusive)   VAT = ฐาน × 7%          มูลค่าก่อนภาษี = ฐาน        ยอดรวม = ฐาน + VAT
โหมดรวมใน  (inclusive)   VAT = ฐาน × 7 ÷ 107     มูลค่าก่อนภาษี = ฐาน − VAT  ยอดรวม = ฐาน
ไม่มี VAT   (none)        VAT = 0                 มูลค่าก่อนภาษี = ฐาน        ยอดรวม = ฐาน

หัก ณ ที่จ่าย = มูลค่าก่อนภาษี(ที่ปัดแล้ว) × อัตรา%     ← คำนวณจากฐานก่อน VAT
เงินที่รับ/จ่ายจริง = ยอดรวม − หัก ณ ที่จ่าย
```

**ลำดับการปัดเศษ** (ทศนิยม 2 ตำแหน่ง ปัดครึ่งขึ้น) — จุดนี้เคยเป็นบั๊กและแก้แล้ว

```
โหมดบวก VAT :  ปัด VAT ก่อน  →  ยอดรวม = มูลค่าก่อนภาษี + VAT(ที่ปัดแล้ว)
โหมดรวม VAT :  ปัด VAT ก่อน  →  มูลค่าก่อนภาษี = ยอดรวม − VAT(ที่ปัดแล้ว)
```

รับประกันว่า **มูลค่าก่อนภาษี + VAT = ยอดรวม เสมอ** และ **ยอดรวม − หัก ณ ที่จ่าย = เงินที่รับจริง เสมอ**

> **บั๊กที่เคยมี (แก้แล้ว 2026-07-26):** เดิมปัดทุกค่าแยกกันจากค่าเต็มความละเอียด
> ทำให้เอกสารบวกกันไม่ลงตัว เช่น ยอด 9.50 โหมดบวก VAT พิมพ์เป็น
> `9.50 + 0.67 = 10.16` (ต้องเป็น 10.17)
> ทดสอบพบ **1,060 กรณีจาก 2 ล้านยอด** · หลังแก้ทดสอบ **63 ล้านกรณี ผิด 0**
> ตรวจเอกสารที่ออกไปแล้วบน production ทั้งหมดแล้ว — ไม่มีใบไหนได้รับผลกระทบ

**ประเด็นที่อยากให้ยืนยัน**
1. ฐานคำนวณหัก ณ ที่จ่ายใช้ยอด**ก่อน** VAT — ถูกต้องตามที่ปฏิบัติจริงหรือไม่
2. ลำดับการปัดเศษข้างต้น (ปัด VAT ก่อนแล้วประกอบยอดรวม) ตรงกับที่โปรแกรมบัญชีมาตรฐานทำหรือไม่ หรือควรใช้วิธีอื่น
3. ระบบไม่รองรับส่วนลดรายบรรทัด (มีเฉพาะส่วนลดท้ายบิล) — เป็นข้อจำกัดที่ยอมรับได้หรือไม่
4. การปัดเศษ VAT ระดับ**ทั้งใบ** (ไม่ใช่รายบรรทัด) ถูกต้องหรือไม่

## 4. การลงบัญชีอัตโนมัติ (`src/lib/finance-server.ts`)

ทุกธุรกรรมลงบัญชีคู่ทันที บังคับ **เดบิตรวม = เครดิตรวม** ถ้าไม่เท่าระบบไม่ยอมบันทึก

| ขายสด (ใบเสร็จ) | เงินสด/ธนาคาร · ภาษีถูกหัก ณ ที่จ่าย (ถ้ามี) | รายได้ · ภาษีขาย |
| ค่าใช้จ่ายเชื่อ | ค่าใช้จ่ายตามหมวด 5xxx · ภาษีซื้อ | เจ้าหนี้การค้า |
| ค่าใช้จ่ายจ่ายสด | ค่าใช้จ่าย · ภาษีซื้อ | เงินสด/ธนาคาร · ภาษีหัก ณ ที่จ่ายค้างนำส่ง |
| รับชำระจากลูกหนี้ | เงินสด/ธนาคาร | ลูกหนี้การค้า |
| จ่ายชำระเจ้าหนี้ | เจ้าหนี้การค้า | เงินสด/ธนาคาร |
| ต้นทุนขาย (ถ้าผูกสินค้า) | ต้นทุนขาย | สินค้าคงเหลือ |
| ยกเลิกเอกสาร | **กลับรายการเดิมทั้งชุด** + คืนสต๊อก | (ไม่ลบรายการเดิม) |

| 1020 | เงินฝากธนาคาร | | 2030 | ภาษีขาย |

**ประเด็นที่อยากให้ยืนยัน**
1. ผังบัญชีตั้งต้น **23 บัญชี** (สินทรัพย์ 6 · หนี้สิน 3 · ทุน 2 · รายได้ 2 · ค่าใช้จ่าย 10 — นับจากฐานข้อมูลจริง) ครอบคลุมพอสำหรับ SME ทั่วไปหรือไม่ และรหัสข้างต้นตรงกับที่นักบัญชีคุ้นเคยหรือไม่
2. ระบบใช้ **เกณฑ์คงค้าง** (บันทึกเมื่อออกเอกสาร ไม่ใช่เมื่อได้เงิน) — เหมาะกับกลุ่มผู้ใช้เป้าหมายหรือควรมีทางเลือกเกณฑ์เงินสด
3. จุดรับรู้ภาษีขาย (tax point) ระบบใช้ **วันที่บนเอกสาร** — ตรงกับหลักความรับผิดในการเสียภาษีหรือไม่ โดยเฉพาะกรณีขายสินค้า (ส่งมอบ) กับให้บริการ (รับชำระ)

## 5. เอกสารที่ระบบออก

| เอกสาร | สถานะความครบถ้วน |
|---|---|
| ใบเสนอราคา | ไม่มีข้อบังคับตามกฎหมาย |
| ใบแจ้งหนี้ | ไม่มีข้อบังคับตามกฎหมาย · **ไม่ใช่ใบกำกับภาษี** (ระบบไม่พิมพ์คำนี้บนใบแจ้งหนี้) |
| ใบเสร็จรับเงิน/ใบกำกับภาษี | ตรวจครบ 8 ข้อตาม ม.86/4 ก่อนพิมพ์ · ขาดข้อไหนขึ้นเตือนแดงและไม่ปล่อยผ่านเงียบ |
| หนังสือรับรองหัก ณ ที่จ่าย (50 ทวิ) | มีคู่สัญญาทั้งสองฝ่าย · ประเภทเงินได้ ม.40 · อัตรา · จำนวนภาษี · แบบยื่นที่เกี่ยวข้อง · เงื่อนไขการหัก · เลขที่อ้างอิง |
| รายงานภาษีขาย/ภาษีซื้อ (ภ.พ.30) | สรุปรายเดือน/ไตรมาส/ปี + ส่งออก Excel |
| ภ.ง.ด.3 / ภ.ง.ด.53 | แยกอัตโนมัติ: เลขผู้เสียภาษี 13 หลักขึ้นต้น 0 = นิติบุคคล → 53 · อื่น ๆ → 3 |
| งบทดลอง | ตามงวดที่เลือก |

### ⚠️ จุดที่ผู้พัฒนายังไม่มั่นใจ — ขอให้ตรวจเป็นพิเศษ

1. **ไฟล์ยื่นสรรพากร (.txt)** — เข้ารหัส TIS-620, วันที่เป็น พ.ศ., คั่นด้วย `|`
   **ยังไม่เคยทดสอบนำเข้ากับโปรแกรม RD Prep จริง** ห้ามใช้ยื่นจริงจนกว่าจะทดสอบ
   ลำดับฟิลด์ที่ใช้: `ลำดับ|เลขผู้เสียภาษี|สาขา|ชื่อ|ที่อยู่|วันที่จ่าย(พ.ศ.)|ประเภทเงินได้|อัตรา|ยอดจ่าย|ภาษีหัก|เงื่อนไข`
2. **การแยก ภ.ง.ด.3 vs 53 ด้วยเลขขึ้นต้น 0** — เป็นวิธีที่ใช้กันทั่วไป แต่ครอบคลุมทุกกรณีหรือไม่ (เช่น ห้างหุ้นส่วนสามัญที่ไม่จดทะเบียน)
3. **อัตราหัก ณ ที่จ่ายที่ระบบแนะนำ** — ระบบมีปุ่มลัด (บริการ 3% · ขนส่ง 1% · โฆษณา 2% · เช่า 5% · วิชาชีพอิสระ 3% · นายหน้า 3% · ลิขสิทธิ์ 3% · ปันผล 10% · ดอกเบี้ย 1%)
   ระบบระบุชัดว่าเป็น**ตัวช่วยกรอก ไม่ใช่คำวินิจฉัยภาษี** และผู้ใช้แก้เองได้เสมอ
   **ขอให้ตรวจว่าอัตราตั้งต้นเหล่านี้ถูกต้องกับปัจจุบัน และควรเพิ่ม/แก้อะไร**
4. **50 ทวิ ไม่ได้ใช้แบบพิมพ์ราชการ** — จัดหน้าเอง ใส่ข้อมูลครบตามที่เข้าใจ ยอมรับได้หรือต้องใช้แบบทางการ

## 7. ข้อจำกัดที่รู้ตัว (ยังไม่ทำ)

- ไม่มีระบบค่าเสื่อมราคาสินทรัพย์ถาวร
- ไม่มีการปรับปรุงรายการสิ้นงวดอัตโนมัติ (ค้างรับ/ค้างจ่าย/รายได้รับล่วงหน้า)
- ไม่มีงบกระแสเงินสดตามมาตรฐาน (มีแต่กราฟเงินเข้า-ออก)
- ไม่มีการปิดบัญชีสิ้นปี/ยกยอดไปงวดถัดไป
- ไม่รองรับหลายสกุลเงิน
- ไม่รองรับ VAT อัตราอื่นนอกจาก 7% และ 0% (ส่งออก)
- ไม่มีทะเบียนสินทรัพย์
- อัตรา VAT 7% ยังฮาร์ดโค้ดอยู่หลายจุด ถ้ากฎหมายเปลี่ยนอัตราต้องแก้โค้ด

## 8. คำถามที่อยากให้ CPA ช่วยตอบ

1. สูตรคำนวณในข้อ 3 ถูกต้องครบถ้วนหรือไม่ โดยเฉพาะฐานหัก ณ ที่จ่ายและการปัดเศษ
2. ผังบัญชีตั้งต้นและคู่บัญชีในข้อ 4 ถูกต้องตามหลักบัญชีที่รับรองทั่วไปหรือไม่
3. จุดรับรู้ภาษีขาย (ใช้วันที่บนเอกสาร) เพียงพอหรือต้องแยกกรณีสินค้า/บริการ
4. ใบเสร็จรับเงิน/ใบกำกับภาษี ที่ระบบออก ใช้ยื่นและให้ลูกค้าขอคืนภาษีซื้อได้จริงหรือไม่
5. หนังสือรับรอง 50 ทวิ ที่จัดหน้าเอง ใช้แทนแบบพิมพ์ราชการได้หรือไม่
6. อัตราหัก ณ ที่จ่ายตั้งต้นที่ระบบแนะนำ ถูกต้องกับปัจจุบันหรือไม่
7. ไฟล์ยื่น ภ.ง.ด. (.txt) รูปแบบถูกต้องหรือไม่ — ขอความกรุณาทดสอบนำเข้า RD Prep จริง
8. ข้อจำกัดในข้อ 7 ข้อไหนที่ **ต้องมี** ก่อนให้ลูกค้าจริงใช้ และข้อไหนรอได้
9. มีอะไรที่ผู้พัฒนามองข้ามและอาจทำให้ผู้ใช้เสียหายทางภาษี/กฎหมาย

## 9. ทางลัดสำหรับผู้ตรวจ — ดึงข้อมูลทั้งงวดเป็นไฟล์เดียว

ที่หน้า **รายงาน + ภาษี** เลือกงวดแล้วกด **"ดาวน์โหลดชุดส่งนักบัญชี"** จะได้ไฟล์ Excel เดียวที่มี 7 แผ่น

| แผ่น | ใช้ทำอะไร |
|---|---|
| อ่านก่อน | ชื่อกิจการ · เลขผู้เสียภาษี · สาขา · งวด · คำอธิบายทุกแผ่น |
| ภาษีขาย | กรอก ภ.พ.30 ฝั่งภาษีขาย (มีคอลัมน์รหัสสาขา 5 หลัก) |
| ภาษีซื้อ | กรอก ภ.พ.30 ฝั่งภาษีซื้อ |
| หัก ณ ที่จ่าย | ระบุแบบที่ต้องยื่น (ภ.ง.ด.3 / 53) ให้รายบรรทัด |
| สมุดรายวัน | รายการบัญชีคู่ทุกบรรทัดในงวด |
| งบทดลอง | ยอดคงเหลือแต่ละบัญชี |
| ลูกหนี้-เจ้าหนี้ค้าง | พร้อมช่วงอายุหนี้ |

สมุดรายวันและงบทดลองสร้างจากชุดข้อมูลเดียวกัน ตัวเลขจึงกระทบยอดกันได้เสมอ

## 10. วิธีตรวจของจริง

1. ขอบัญชีทดลองจากเจ้าของระบบ แล้วเข้า **ภาพรวม → ลองด้วยข้อมูลตัวอย่าง** จะได้เอกสารตัวอย่าง 4 ใบพร้อมรายการบัญชี
2. **สมุดรายวัน** — ดูว่าทุกรายการเดบิต = เครดิต และคำแปลภาษาคนตรงกับที่เกิดขึ้นจริง
3. **รายงาน + ภาษี** — เทียบ ภ.พ.30, ภ.ง.ด., งบทดลอง กับเอกสารต้นทาง
4. ออกใบเสร็จที่คิด VAT แล้วกด **พิมพ์** — ตรวจครบ 8 ข้อตาม ม.86/4
5. บันทึกค่าใช้จ่ายที่มีหัก ณ ที่จ่าย แล้วพิมพ์ **50 ทวิ**
6. ทดสอบว่าลบข้อมูลกิจการ (ชื่อ/เลขภาษี/ที่อยู่) แล้วพิมพ์ใบกำกับภาษี — ต้องขึ้นเตือนแดง ไม่ยอมให้พิมพ์เงียบ ๆ

**ติดต่อกลับ:** แจ้งข้อที่ไม่ถูกต้องมาได้เลย ทีมพัฒนาจะแก้แล้วให้ตรวจซ้ำ

## 11. บันทึกการแก้ตามผลตรวจ (ปรับปรุง 26 ก.ค. 2569)

ผู้สอบบัญชีตรวจรอบแรกแล้วชี้ประเด็นไว้ ส่วนนี้บันทึกว่าแก้อะไรไปแล้วบ้าง
และอะไรที่ยัง **ไม่** แก้พร้อมเหตุผล เพื่อให้การตรวจรอบสองดูเฉพาะส่วนที่เปลี่ยน

### แก้แล้ว — ยืนยันด้วยข้อมูลจริงบน production

| ประเด็น | เดิม | แก้เป็น | หลักฐาน |
|---|---|---|---|
| อัตรา VAT ฮาร์ดโค้ด | เลข 7% ฝังในโค้ด | ตาราง `vat_rates` + `vat_rate_on(date)` เลือกตามวันที่ออกเอกสาร + แบนเนอร์เตือนก่อนหมดอายุ | 1 ต.ค. 2569 และ 1 ม.ค. 2570 ยังคืน 0.07 ระบบไม่เปลี่ยนอัตราเอง |
| ภาษีขายนับซ้ำข้ามเดือน | ใบแจ้งหนี้ มิ.ย. + ใบเสร็จ ก.ค. นับ VAT สองรอบ | `selectVatSalesDocs()` นับที่ใบแจ้งหนี้เสมอ ใบเสร็จที่แปลงมาไม่นับซ้ำ | จำลอง: ที่ถูก 700 · กฎเดิม 1,400 · กฎใหม่ 700 |
| ชุดส่งสำนักงานบัญชีรวมใบเสนอราคา | แท็บภาษีขายรวมทุกอย่างที่ไม่ใช่ค่าใช้จ่าย | ใช้ฟังก์ชันกลางตัวเดียวกับหน้าจอ | จำลอง: กฎเดิม 1,750 · กฎใหม่ 700 |
| รายงานไม่ตรงสมุดรายวัน | คนละกฎกัน | กฎเดียวกัน ผูกกับการลงบัญชี | ทุกเดือนทุกกิจการ ผลต่าง 0.00 |
| งบทดลองในไฟล์ | รวมเฉพาะรายการในงวด แต่พาดหัวว่า "ยอดคงเหลือ ณ สิ้นงวด" | ยอดสะสมถึงก่อนวันสิ้นงวด + แถวรวม + เตือนถ้าเดบิต≠เครดิต | ใช้กติกาเดียวกับแท็บงบทดลองบนหน้าจอ |
| ภ.ง.ด.3 vs 53 | เดาจากเลขผู้เสียภาษีขึ้นต้น 0 | ฟิลด์ "ประเภทผู้รับเงิน" (บุคคลธรรมดา / นิติบุคคล / คณะบุคคล–ห้างหุ้นส่วนสามัญไม่จดทะเบียน) ผู้ใช้เลือกเอง snapshot ลงเอกสาร | คณะบุคคลที่เลขขึ้นต้น 0 เข้า ภ.ง.ด.3 ถูกต้องแล้ว |
| เลขผู้เสียภาษีพิมพ์ผิด | ไม่ตรวจ | ตรวจ check digit ตอนกรอก | สูตร ผลรวม(หลักที่ i × (13−i)) → (11 − เศษ) mod 10 |
| รหัสสาขาในไฟล์ยื่นภาษีขาย/ซื้อ | ฮาร์ดโค้ด `00000` ทุกบรรทัด | ใช้สาขาจริงของคู่ค้าแต่ละราย | |
| เกณฑ์ 1,000 บาท | ไม่มี | เตือนเมื่อยอดก่อน VAT ต่ำกว่าเกณฑ์ (เตือนอย่างเดียว ไม่บล็อก เพราะสัญญาต่อเนื่องยังต้องหัก) | ท.ป.4/2528 |
| แบนเนอร์/ปุ่มลอยติดไปบนใบกำกับภาษี | พิมพ์ออกมาด้วย | กัน `data-noprint` ทั้งหมด | |
| **ใบลดหนี้ (ม.86/10) / ใบเพิ่มหนี้ (ม.86/9)** | ไม่มี — ต้องยกเลิกใบเดิม ซึ่งข้ามงวดภาษีทำไม่ได้ | ออกจากใบกำกับภาษีเดิมได้โดยตรง · ลงวันที่ในเดือนที่เหตุเกิดตามกฎหมาย จึงไม่ชนล็อกงวด · **ใช้อัตรา VAT ของใบเดิม ไม่ใช่อัตราวันนี้** · ลดเกินยอดใบเดิมไม่ได้ · เอกสารพิมพ์อ้างเลขที่+วันที่ใบเดิมและเหตุผลตามที่กฎหมายบังคับ · เข้า ภ.พ.30 เป็นยอดติดลบทั้งบนจอ ใน Excel และในไฟล์ยื่น | ทดสอบ: เดบิต 2,140 = เครดิต 2,140 · ภาษีขายสุทธิ 700−140 = 560 · บัญชี 4090 รับคืนและส่วนลดจ่าย ลงเดบิต 2,000 ไม่ไปลบยอดขาย |
| **ล็อกงวดที่ยื่นภาษีแล้ว** | ไม่มี — แก้ตัวเลขงวดที่ยื่นไปแล้วได้ | ตาราง `fin_period_locks` + **trigger ที่ฐานข้อมูล** (`assert_period_open`) บังคับทุกทางพร้อมกัน รวมถึงตอนผู้ช่วย AI ลงบัญชีให้ และรวมถึง service_role · ปลดล็อกได้เฉพาะเจ้าของ และถูกบันทึกใน `audit_logs` | ทดสอบ 6 กรณี: ห้ามแก้ยอด/ห้ามยกเลิก/ห้ามย้ายวันที่/ห้ามลงบัญชีย้อน = บล็อกครบ · **รับชำระใบเก่ายังทำได้** และออกเอกสารงวดปัจจุบันได้ปกติ |
| ไฟล์ยื่นสรรพากรรั่ว | เนื้อไฟล์ถูกส่งไปเบราว์เซอร์ทุกแพ็กเกจ ล็อกแค่ปุ่ม | ไม่ส่งเนื้อไฟล์เลยถ้าแพ็กเกจไม่ถึง | |

### ยังไม่แก้ — พร้อมเหตุผล

1. **จุดความรับผิด VAT แยกสินค้า/บริการ (ม.78 กับ ม.78/1)** — ยังไม่มีฟิลด์ประเภทรายการระดับบรรทัด
   ระบบยึดจุดความรับผิดแบบสินค้า (ออกใบกำกับภาษี ณ วันออกใบแจ้งหนี้) กับทุกใบ
   บัญชี 2035 "ภาษีขายยังไม่ถึงกำหนด" และ 1156 "ภาษีซื้อยังไม่ถึงกำหนด" เตรียมไว้ในผังบัญชีแล้ว รอ flow
   **ทางออกชั่วคราวที่แนะนำผู้ใช้:** ธุรกิจบริการล้วน ให้ออกใบเสร็จรับเงินตอนรับเงิน ไม่ต้องออกใบแจ้งหนี้ก่อน
2. ~~ใบเพิ่มหนี้ / ใบลดหนี้~~ — **ทำแล้ว** ดูตารางด้านบน
3. ~~ล็อกงวดที่ยื่นแล้ว~~ — **ทำแล้ว** ดูตารางด้านบน
4. **ปิดบัญชีสิ้นปี / ยกยอดกำไรสะสม และค่าเสื่อมราคา** — ยังไม่มี บัญชี 1210 / 1290 / 5210 เตรียมไว้แล้ว
5. **ไฟล์ยื่น RD Prep ยังไม่เคยทดสอบนำเข้าโปรแกรมจริง** — รูปแบบอิงเอกสาร ยังไม่รับรองว่านำเข้าผ่าน
