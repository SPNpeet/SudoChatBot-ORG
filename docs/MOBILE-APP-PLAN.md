## 5. 🚨 จุดเสี่ยง — เรียงตามความเสียหาย

### 5.1 🔴 ส่วนแบ่งสโตร์ (เรื่องธุรกิจ ไม่ใช่เทคนิค)
ดูข้อ 3 · **สถานะในโค้ดตอนนี้: ไม่มีปุ่มจ่ายเงินในแอป = ปลอดภัยที่สุด**

### 5.2 🔴 แคชผิด = ผู้ใช้เห็นตัวเลขบัญชีเก่า
ถ้า service worker หรือ WebView แคชหน้ายอดลูกหนี้/รายงานภาษี ผู้ใช้จะเห็นเลขเก่า
แล้วตัดสินใจ (หรือยื่นภาษี) จากเลขนั้น
**กติกา: ทุกหน้าที่มีตัวเลขเงินหรือภาษีต้อง network-first เสมอ** แคชได้แค่ไฟล์นิ่ง

### 5.3 🔴 แอปเวอร์ชันเก่าค้างกฎภาษีเก่า
แก้แล้วที่ระดับสถาปัตยกรรม (ชี้ URL จริง ดูข้อ 1) — **ห้ามเปลี่ยนไป bundle เด็ดขาด**
ยังควรเพิ่ม: endpoint คืนเวอร์ชันขั้นต่ำที่ยอมรับ เพื่อบังคับอัปเดตเมื่อจำเป็น

### 5.4 🟠 ข้อมูลบัญชีค้างบนเครื่องที่หาย (PDPA)
มือถือหายบ่อยกว่าคอมมาก
- token ต้องอยู่ใน Keychain (iOS) / EncryptedSharedPreferences (Android) — **ห้าม localStorage**
- ต้องมีปุ่ม "ออกจากระบบทุกอุปกรณ์" · ล็อกแอปด้วยไบโอเมตริกเมื่อเปิดจากพื้นหลัง
- **ห้ามแคชไฟล์เอกสาร/สลิปลงเครื่องถาวร**

### 5.5 🟠 โดนตีตกตอนส่งสโตร์
- **"แอปเป็นแค่เว็บไซต์"** (Apple 4.2) → ต้องใช้ความสามารถเครื่องจริงให้เห็น
  **ทางแก้ที่เตรียมไว้แล้ว: กล้องถ่ายบิล · push · แชร์ไฟล์** (ปลั๊กอินติดตั้งครบแล้ว)
- **ไม่มีบัญชีทดสอบให้ reviewer** → ตกทันที
- **ไม่มีวิธีลบบัญชีในแอป** → ทั้งสองสโตร์บังคับ · มีหน้า `/data-deletion` แล้ว
  แต่ต้องเข้าถึงได้จากในแอป
- **ขอสิทธิ์โดยไม่อธิบาย** → แก้แล้ว (Info.plist 3 ข้อความภาษาไทย · manifest ขอเท่าที่ใช้)

### 5.6 🟠 กล้อง OCR บนมือถือจริงต่างจากที่ทดสอบ
บิลไทยส่วนใหญ่เป็นกระดาษความร้อนที่จาง ถ่ายในร้านแสงน้อย เอียง มีเงามือ
ระบบมีตัวจับผิด OCR อยู่แล้ว (ทานยอดท้ายบิลกับผลรวมที่คำนวณเอง เกิน 5 สตางค์ = เตือน)
**ห้ามตัดออกในแอปเพื่อความลื่น**

### 5.7 🟡 ค่า AI พุ่งเมื่อใช้ง่ายขึ้น
แอปทำให้ถ่ายบิลง่ายขึ้นมาก → OCR จะพุ่ง และ OCR แพงกว่าแชท ~8 เท่า
เกราะที่มี (`ocrMonthlyGuard` + kill switch + เพดานรายวัน) ต้องถูกเรียกจากเส้นทางแอปด้วย
**ห้ามเปิด API ใหม่สำหรับแอปที่ข้ามเกราะเหล่านี้** — เคยเกิดแล้วกับ `/api/products/import-extract`

### 5.8 🟡 ยังไม่มีไฟล์สำรอง "ออกนอกฐานข้อมูล"

**ตรวจแล้ว 12 ส.ค. — ชั้นสำรองในฐานข้อมูลทำงานจริง ไม่ใช่ไม่มีอะไรเลย:**

| ตรวจอะไร | ผลที่วัดได้ |
|---|---|
| `snapshot_status()` | `snapshot_2026_08_12` · **70 ตาราง** |
| cron | `daily_db_snapshot @ 0 21 * * *` (ตี 4 ไทย) · active |
| ข้อมูลครบไหม (เทียบ snapshot กับของจริง) | `fin_docs` 102=102 · `journal_lines` 319=319 · `shops` 32=32 ✅ |

**สิ่งที่ยังขาดคือสำเนา "นอกโปรเจกต์"** — snapshot อยู่ในฐานข้อมูลเดียวกัน
กัน migration พลาด/ลบผิด/ตารางเสียได้ แต่**ไม่กันกรณีทั้งโปรเจกต์หาย**
ปิดช่องนี้ได้ 2 ทาง: ตั้ง `CRON_SECRET` ใน Vercel (อัตโนมัติทุกคืน)
หรือกดปุ่มสำรองในหน้าแอดมิน / `npm run backup` เป็นระยะ (ทำเอง)

## 7. สิ่งที่เอกสารนี้ยังไม่ได้ยืนยัน (พูดตรง ๆ ตามกติกาข้อ 5)

- **APK ยังไม่เคยถูกเปิดบนมือถือจริง** — ไม่มีเครื่อง Android และ **อีมูเลเตอร์รันไม่ได้เพราะเครื่องนี้ไม่มี KVM**

  สิ่งที่ตรวจแทนได้และผ่านหมด (แกะไฟล์ APK ออกมาดูจริง) — จับบั๊กร้ายแรงที่สุดได้คือ
  "URL ที่ฝังในแอปผิด แล้วเปิดมาเจอหน้าออฟไลน์ตลอดกาล":

  | ตรวจอะไร | ผล |
  |---|---|
  | `assets/capacitor.config.json` ที่ฝังในแอป | `server.url = https://sudochatbot.online` ✅ · `allowNavigation` ครบ ✅ |
  | หน้าสำรองที่ถูกใส่ไปด้วย | เป็นหน้าที่เราเขียนจริง (พบข้อความไทย "ต่ออินเทอร์เน็ตไม่ได้") ✅ |
  | activity ที่เปิดได้ | `online.sudochatbot.app.MainActivity` label `SudoChatBot` ✅ |
  | สถาปัตยกรรมเครื่องที่รองรับ | arm64-v8a · armeabi-v7a · x86 · x86_64 (ครอบมือถือยุคนี้ทั้งหมด) ✅ |

  **ที่ยังพิสูจน์ไม่ได้เหลืออย่างเดียว: เปิดแล้วเห็นหน้าเว็บจริงไหม** ต้องมีคนติดตั้งลองเปิด
- **ฝั่ง iOS ยังไม่เคย build** — compile ต้องใช้ macOS + Xcode ซึ่งไม่มีในเครื่องนี้

  แต่**ตรวจโครงโปรเจกต์ครบแล้วเพื่อให้เปิดบน Mac แล้ว build ผ่านตั้งแต่ครั้งแรก**
  (ดักปัญหาตอนนี้ ดีกว่าไปเจอตอนนั่งอยู่หน้าเครื่อง Mac):

  | ตรวจอะไร | ผล |
  |---|---|
  | `Info.plist` เป็น plist ที่ถูกต้อง | อ่านผ่าน · 21 keys ✅ |
  | ข้อความขอสิทธิ์ 3 ตัว | Camera · PhotoLibrary · PhotoLibraryAdd ครบ เป็นภาษาไทย ✅ |
  | ชื่อ/หน้าเปิดแอป | `CFBundleDisplayName = SudoChatBot` · `UILaunchStoryboardName = LaunchScreen` ✅ |
  | `capacitor.config.json` ที่ sync เข้า iOS | `server.url` ถูกต้อง ✅ |
  | ปลั๊กอินผูกเข้า SPM | ครบทั้ง 7 ตัว (App · Browser · Camera · Filesystem · PushNotifications · Share · StatusBar) ✅ |
  | หน้าสำรองตอนเน็ตหลุด | sync เข้า `ios/App/App/public/` แล้ว ✅ |

  **เหลือแค่ขั้นตอนที่ต้องใช้เครื่อง Mac จริง:** เปิด `ios/App/App.xcodeproj` → เลือกทีมพัฒนา
  (Signing & Capabilities) → กด Run · ถ้าจะส่ง Push ต้องเพิ่ม capability "Push Notifications"
  และอัปโหลด APNs key ใน Apple Developer Console
- **กฎ In-App Purchase ฉบับล่าสุด** — ข้อ 3 เขียนจากหลักการที่ใช้กันทั่วไป ต้องเปิดกฎจริงก่อนส่ง
- **`public/sw.js` แคชอะไรบ้าง** — รู้ว่ามีไฟล์และมีโค้ดลงทะเบียน แต่ยังไม่ได้ไล่อ่านเนื้อใน
